# Безопасность

Если нашёл уязвимость (например, способ подсунуть виджетам iPhone чужое обновление, выполнить чужой код
на сайте или получить доступ к чьим-то данным), не публикуй детали в открытом Issue.

Напиши на почту проекта **zvonok165lyceumalmaty@gmail.com** или через [форму на сайте](https://danick-dack.github.io/Zvonok/feedback.html)
(тип «Ошибка», без подробностей, мы сами свяжемся). Опиши, что нашёл и как это повторить.
Ответим в течение недели и скажем, когда исправим.

## Что уже защищено

- Сайт: строгая политика CSP по хешам, без внешних скриптов и трекеров.
- Виджеты и приложение на iPhone ставят новую версию, только если она подписана ключом «Звонка» (Ed25519).
  Закрытого ключа в репозитории нет, он хранится в секретах GitHub Actions.
- Приложение Android подписано постоянным ключом, ходит в интернет только по HTTPS и только на сайт «Звонка» и GitHub.
- Контрольная сумма SHA-256 каждого APK есть в описании релиза.

## Какие версии поддерживаются

Исправления выходят только для последней версии. Официальные сборки только в
[Releases](https://github.com/Danick-Dack/Zvonok/releases) этого репозитория и на сайте danick-dack.github.io/Zvonok.

## Как мы бережём людей

«Звонком» пользуются школьники, поэтому главное правило: не собирать того, что можно потерять.

- **Данных о людях нет.** Нет аккаунтов, паролей, имён, оценок и переписки. Класс, кружки, фон и настройки лежат
  только на устройстве. Утекать нечему.
- **Счётчик без слежки.** Число устройств за сутки считает GitHub по скачиваниям пустого файла из релиза.
  Мы не видим и не храним IP и ничего об устройстве.
- **Чужой текст не выполняется.** Новости, замены, олимпиады и своё расписание показываются только как текст.
  Сайт собирает страницы без `innerHTML` для данных, со строгой CSP по хешам; ссылки в постах открываются только по `http(s)`.
- **Новости проходят через сборку.** В Telegram с устройств никто не ходит. Сборка сайта забирает публичное превью
  канала, оставляет текст и одну картинку. Картинки берутся только с серверов Telegram по HTTPS и пересохраняются,
  так что в файле остаются одни пиксели. Приложения принимают картинки только из папки `news/` своего сайта и не больше 600 КБ.
- **Свои объявления** лежат в `data/news.json`, фото к ним в `data/news/`. Сборка проверяет каждое поле как чужой текст
  и пересохраняет фото без метаданных, так же как картинки канала.
- **Файлы с сайта проверяются.** Расписание, замены и новости приложения читают с проверкой формата и размера:
  кривой или подменённый файл не роняет приложение, а пропускается.
- **Обновления подписаны.** Android ставит APK только с той же подписью. iPhone ставит новую версию скрипта только
  с подписью Ed25519 и не старее текущей.
- **Минимум разрешений.** Android: уведомления и интернет (новая версия, замены, новости лицея). Ни контактов, ни камеры, ни геолокации,
  ни доступа к галерее: фото для фона человек выбирает сам в системном окне. Резервное копирование данных выключено,
  открытый текст (HTTP) запрещён, наружу открыты только главный экран, плитка и виджеты.
- **Сборка.** Секреты (ключ подписи APK и ключ обновлений iPhone) хранятся в GitHub Actions. Проверки на каждый
  коммит: данные, тесты сайта, тесты Android, сверка правил между платформами, CodeQL, Dependabot.
  Менять `main` может только владелец (CODEOWNERS).

## Что стоит включить владельцу репозитория

В настройках GitHub (Settings): защита ветки `main` (только через Pull Request, обязательные проверки),
Secret scanning и Push protection, двухфакторная защита аккаунта, право на запись в Actions только там, где оно нужно.
